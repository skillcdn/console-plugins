# ADR-0005: A plugin is versioned on the console's line, with a patch of its own

- Status: Accepted
- Date: 2026-11-06
- Amends [ADR-0002](0002-one-package-per-plugin-published-to-the-registry-under-one-scope-and-versioned-on-its-own.md) (point 3, how a plugin's version is bumped) and [ADR-0003](0003-every-plugin-is-built-against-one-version-of-the-console-and-they-move-together.md) (point 2, what moving to the next line does to the versions); the rest of both stands. The rule is held by `scripts/check-version-line.mjs`; what a changeset says is in [.changeset/README.md](../../.changeset/README.md), and the procedure in [guide/releasing.md](../guide/releasing.md).

## Context

ADR-0002 gave each plugin a version of its own under semver, `minor` for something new and for a breaking change before 1.0, and ADR-0003 made every plugin move to the console's next line together, with a `minor` changeset each. Read together, a plugin's number said nothing of the console it runs on: `@skillcdn/console-plugin-hr` 0.7.2 might be built for a console 0.4 or 0.6, and whoever installs it would learn which from the changelog alone, where the one thing a deployment must know before installing a plugin is whether it goes with its console. Before 1.0 the plugin API moves with the console's line and a plugin is rebuilt against the console it runs on (the contract, "Authoring"); a deployment pins its console and its plugins at exact versions, and upgrades the console first.

The console met the same question with the SkillCDN packages it is built on and settled it, after three decisions in a day, by mirroring: its major and minor are SkillCDN's line, its patch its own, lines adopted in order with one `minor` changeset each, and within a line every release a `patch` whose entry says `Breaking:` first where it changes what exists ([ADR-0034 of the console](https://github.com/skillcdn/console/blob/main/docs/adr/0034-the-package-is-versioned-on-skillcdns-line-one-line-at-a-time-with-a-patch-of-its-own.md)). The packages that mirror an upstream's version are the precedent: a component library carries the framework's major and minor, the typings packages those of the library they type.

## Decision

1. **The version is the console's line with a patch of the plugin's own.** The major and the minor of every published plugin are those of the `@skillcdn/console` it is built against, the catalog's, as the lockfile resolves it; the patch counts the plugin's releases on that line. `@skillcdn/console-plugin-hr` 0.4.x is the HR plugin for a console 0.4.x. The plugins of this repository share a line and each has a patch count of its own: a plugin that did not change is not re-released within a line, and its changelog is its own (ADR-0002 stands).
2. **Lines are adopted in order, one `minor` each.** The console's next line moves the catalog, rebuilds every plugin and is a `minor` changeset for each published one (ADR-0003 stands), and the version pull request lands every plugin on `<line>.0`. Within a line every release is a `patch`. Never a `major` while the major is 0; a plugin's 1.0.0 waits for the console's, whose contract is declared stable then.
3. **A patch is read by its entry.** Within a line, a release that changes or removes what exists, a command or its arguments, a query's answer, a role, a setting, a capability asked anew, says so first in its changelog entry, as `Breaking:`, and whoever installs reads the entry before taking it; a change to the shape of a plugin's records raises `dataVersion` with an `upgrades` entry in the same change, and the entry says so (ADR-0002 stands). Where a release needs a later patch of the console's line than the one before it, the entry names it: "built for console 0.4.3 or later".
4. **The one number ever written by hand is a new plugin's first.** A plugin leaves `private` at the previous line's `.0`, a version never published, beside its first `minor` changeset, so that the version pull request lands it on `<line>.0`, which a maintainer publishes by hand from that pull request (ADR-0002, point 2). A line this repository skipped is reached the same way, the version set to the previous line's `.0` beside the `minor` changeset. A private plugin, the example `hello`, is never versioned, whatever number the template wrote, and is not held to the line.
5. **The rule is checked.** `pnpm check` fails when the catalog's range and the lockfile's resolution of `@skillcdn/console` name different lines or more than one version; when a published plugin's major and minor are not the line, unless it is one line behind with a `minor` changeset pending; when a changeset asks `minor` of a plugin already on the line, or `major` of any (`scripts/check-version-line.mjs`).

## Consequences

- A deployment keeps its console and its plugins on one line: the number says at a glance what goes with what, a patch of either is taken with its entry read, and the next line is one step the console takes first.
- A plugin's changelog says what each patch changed for whoever installs it, `Breaking:` where it did; the number does not, as the console's number does not.
- Moving to the console's next line is one pull request that re-releases every published plugin at `<line>.0`, which ADR-0003 wanted anyway. The patch counts start over on every line.
- The console does not check which patch of its line a plugin was built for: a plugin on a console older than the patch it was built for may miss what that patch added. The hand-over task names the floor, and a field of the manifest the console reads at load is proposed to the console.
- Rejected: a version of each plugin's own with the line as data in the changelog (what ADR-0002 had: the number said nothing of the console, and the plugins of one deployment carried unrelated numbers); the version computed from the console's at pack time (the manifest in the repository would not say what the registry shows, and the changelog's heading would be a tool's of our own); `minor` for a plugin's own breaking change (the minor is the console's line); a peer dependency on `@skillcdn/console` (a deployment's install would pull the console into the plugins' directory, and nothing of the console reads it).
