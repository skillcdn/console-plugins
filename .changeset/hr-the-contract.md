What other plugins hear of `hr` and may call is its contract, written in the README's "The contract" and held to the code by a test: the events, each with its data and the order they come in; an `api` for a plugin with `plugins:hr` (`request-view`, `types`, `balance`, `preview`, `request`, `cancel`), each the command or the query of that name under the caller's roles; and the option keys `approve` and `reject` of every decision. The query `request-view <id>` reads one request in full, for the person, those above them, its line and HR. A cancellation that waits for a decision is the event `leave-cancelling`. A request keeps whom its decision was addressed to where the console sent it on up the line, so that `requests --scope waiting`, Approvals and the overview show it to whoever it waits for: the records move to `dataVersion` 2, and the upgrade writes the field for every request.
